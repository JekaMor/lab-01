# findex

Лаба 1 з Python: читаємо корпус текстів потоком, ріжемо на токени й рахуємо
статистику, не завантажуючи все в пам'ять.

## Корпус

40 книг з [Project Gutenberg](https://www.gutenberg.org/), приблизно 30 МБ і 5,3 млн
слів. У git їх немає (`data/` у `.gitignore`), завантажити можна так:

```bash
python scripts/download_corpus.py data
```

## Як запустити

```bash
uv sync
uv run pytest
uv run ruff check .
uv run python -m findex.stats data/              # ледача версія, один прохід
uv run python -m findex.stats data/ --limit 5    # тільки перші 5 документів
uv run python -m findex.stats data/ --eager      # версія зі списками, для порівняння
```

Програма виводить кількість документів і токенів, розмір словника, топ-50 слів, час
роботи та піковий об'єм пам'яті.

## Що де лежить

- `src/findex/corpus.py` — `iter_documents`: генератор, який віддає по одному
  `.txt` файлу. Якщо файл із битим UTF-8, пише в лог і читає із заміною символів. Якщо
  файл зник посеред читання, пише в лог і йде далі.
- `src/findex/tokenize.py` — `tokenize`: генератор токенів.
- `src/findex/stats.py` — підрахунок статистики (ледачий і жадібний варіанти) та
  команда `python -m findex.stats`.
- `tests/` — 22 тести.

## Як працює токенізатор

1. Текст приводиться до NFC і до нижнього регістру через `casefold()`. Тому `Straße`
   стає `strasse`, а `é`, записане як `e` + діакритика, збігається зі звичайним `é`.
2. Токен — це послідовність літер і цифр будь-якої мови, тож кирилиця працює.
3. Апостроф усередині слова лишається (`don't`, `п'ять`), різні види апострофів
   зводяться до звичайного `'`. Апострофи на краях слова відкидаються.
4. Дефіс розділяє слова: `well-known` дає `well` і `known`.
5. Цифри теж токени: `3.14` дає `3` і `14`, а `abc123` лишається одним словом.
6. Підкреслення вважається розділювачем.
7. Недолік: якщо літера з діакритикою не має готового одного символу в Unicode, слово
   розірветься на місці діакритики.

## Вимірювання

Однаковий корпус (40 документів, 5 276 209 токенів, 68 213 різних слів), та сама
машина. Обидві версії запускались під `tracemalloc`, а він уповільнює програму, тому
час тут завищений. Порівнювати варто рядки між собою.

| Версія | Документів | Пікова пам'ять | Час |
|---|---|---|---|
| eager (списки) | 40 | 321,7 МіБ | 15,37 с |
| lazy (генератори) | 40 | 52,1 МіБ | 14,73 с |

### Чому так

У версії зі списками одночасно лежать усі тексти (близько 30 МіБ) і всі 5,3 млн
токенів, кожен як окремий рядок Python у списку. Кожен такий рядок займає десятки
байтів, і разом це сотні мегабайт. Звідси майже вся різниця.

Ледача версія тримає лише поточну книгу (найбільша — 3,3 МБ, і нормалізація робить
кілька її копій) та `Counter`, де кожне з 68 тисяч різних слів записане один раз.
Через це пам'ять невелика, але не нульова. Якщо корпус збільшити вдесятеро, ледача
версія залишиться приблизно на тому ж рівні, а версія зі списками виросте вдесятеро.
Час майже однаковий, бо робота та сама, відрізняється тільки те, де лежать дані.
